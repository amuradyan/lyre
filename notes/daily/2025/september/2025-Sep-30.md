# Daily Note - September 30, 2025

## Issues from Previous Notes

The core challenge is making Lyre syntax look and feel more musical. Current syntax with `sequence`, `parallel`, and `tone` is too verbose and implementation-focused rather than expressing musical ideas naturally. We need a macro system to enable syntax sugar for compact time notation (`.A4`, `:A4`, `.:A4`) and more musical terminology like `harmony` instead of `parallel`. This all points toward designing macros that can transform musical notation into the underlying implementation primitives.

Logo color needs refinement - the purple "y" highlighting the reverse lambda is conceptually right but the specific shade needs work.

----

We don't need no macro system so far. If we write it like so

```lisp
(set! . 250) ; set time unit to 250ms

(harmony
  ,(::D3       | ::D3      )
  ,(:A5 F#5 G5 | :A5 F#5 G5))
```

We can just preprocess the code to expand the `,` expressions into the full forms - `sequence` in this case. Just like the quote in Lisp, we shall _comma_ what we find important and just like _quote_ we will expand it, but to a different thing as fundamental in Lyre

We can also split the note sequences by `|` to provide a better visual structure of the music, and the implementation is nearly free - just treat it as whitespace. Awesome!
