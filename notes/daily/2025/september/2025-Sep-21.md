## On Content-Based Code Block Storage

Discovered and fixed indexing issue with code block storage system.

**Problem**: When we made blocks without tests read-only (static blocks), it changed the sequential indexing and broke saved solutions for interactive blocks below them.

**Root Cause**: Original storage used `slideId-blockIndex` (sequential integers) which broke when blocks were added/removed/reordered.

**Solution**: Implemented content-based hashing system:

- Each block gets hash based on initial code content (e.g., `"abc123def"`)
- Storage key becomes `slideId-contentHash` instead of `slideId-blockIndex`
- Blocks maintain identity regardless of position

**Implementation**:

- Added `hashContent()` function using simple hash algorithm
- Updated `saveCodeBlock()` and `loadCodeBlock()` to use content hash
- Modified components to pass initial code content for hashing
- Backwards compatible (old keys simply not found)

**Benefits**: Blocks can be freely reordered, static blocks don't break interactive ones, more robust than position-based storage.
