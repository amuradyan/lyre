# 2025-Oct-07

## Navigation Button UX Refinement

The slide navigation buttons needed better visual clarity. We iterated through several designs before landing on a split-button approach that feels intuitive. The next button now shows `| Title > |` when there's no skip option, keeping the title and chevron together as a unified action. When exercises can be skipped, it becomes `| Title > ||>> |` where the double chevron appears as a second button sharing the border with the first.

The key insight was treating the skip as an extension of the next button rather than a separate element. Both buttons share a border where they meet, creating a visual unit that suggests related but distinct actions. The double chevron communicates "skip ahead further" while the single chevron means "proceed normally." This also mirrors the back button's spacing and creates a consistent navigation experience across the slides.

## Interactive Slide Navigation

Added a clickable slide index counter between navigation buttons. The counter shows current position (e.g., "2/5") and turns indigo on hover. Clicking it opens a modal listing all slides by number and title, with the current slide highlighted.

---

Slides config now auto-generates from markdown files using `import.meta.glob` - titles extracted from headings, sorted by filename numbers.

## On saving slide code

When at least one test is present, the slide code is saved automatically on every change. This ensures that progress isn't lost and tests can be run against the latest code.

## Collapsible Content and Image Support

Added two content enhancements to the markdown parser and slide renderer:

**Collapsible paragraphs** use `>+` prefix syntax to create expandable content. Default state is collapsed, showing the first 10 words with "... (click to expand)". Click anywhere to toggle full text. Visual indicator shows `+` when collapsed, `−` when expanded. This allows detailed explanations to be hidden until readers need them, keeping slides cleaner.

**Image rendering** supports both web URLs (`https://...`) and local file paths (relative to notes directory). The renderer automatically handles path resolution for dev (`/@fs`) and production (`/notes/`) environments. Supports all browser-compatible formats: PNG, GIF, JPG, SVG, etc. Markdown syntax is standard: `![alt text](url or path)`.
