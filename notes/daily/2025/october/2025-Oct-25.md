## On code too long for test box

I got to a point where JS exercises become quite long and consisting of several functions. This leads to a tall code block. I need to figure out how to reference already written code. I am thinking of maybe tabs with names and code editors like files, and an import kind of a thing.

Generally, thinking about the code block as a file can be helpful later on when we implement the saving the code to github. Going with real ES6 import/export syntax where each tab is a file - students use actual JavaScript modules, and we transform them behind the scenes by injecting into evaluation context. This teaches real syntax and sets up nicely for later GitHub integration.
