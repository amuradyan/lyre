## On test display bug with mutable operations

While working on the Lists slide, I noticed tests were displaying incorrectly for functions that mutate their arguments like `push()`. The test would show `f([1], 1)` as `f([1, 1], 1)` because the display was reading inputs after the function had already modified them.

----

The robot fixed this by deep cloning inputs before function execution, preserving the original values for display. Also improved array formatting to show proper bracket notation for nested arrays.

## On exercise creation pattern

I formalized the pattern for creating exercises: the robot proposes 7 options, and I select 3-4 to include. Each exercise needs:

- Real-world framing /very important - relatable contexts like shopping, weather, seating/
- Progressive difficulty with decreasing scaffolding
- Fill-in-blanks with `???`
- Test cases that display cleanly
