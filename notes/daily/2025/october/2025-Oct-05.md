## On test runner simplification and format consistency

Today while writing the redshift exercise, I discovered the test runner was broken - it wasn't displaying the function call when tests passed... or that's what I thought. The robot dug in and we realized the runner had overly complex branching logic that tried to deduce test type from syntax, treating single objects differently from arrays in confusing ways.

We fixed it by removing the special cases and standardizing on two simple formats: arrays `[{inputs: [...], expected: ...}]` for function tests where the runner calls the function multiple times, and plain values like `0.25` for tests where the code already includes the function call.

Much cleaner and predictable now, tough the function call is not being displayed still, but it is ok, since in this case the code already includes the function call.
