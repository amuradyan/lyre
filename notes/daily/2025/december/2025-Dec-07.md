## On structure of `synth` chapter

I was thinking to so harmony, silence and loops in this chapter, but came to realization that the last two are conveniences, and the latter is not common in music sheets. Instead, I'll do filters and try to mimic lyre string pluck with overtones and all. Maybe drop in a few wave forms too, but not silence and loops.

Conveniences will go to a separate chapter, where we might also explore concise syntax for `sequence` for example, and generally think of how we want the language to look like.

----

The key to realistic plucked lyre strings is not LFO or oscillator sync - it's the combination of low-pass filter with dual envelopes. Real plucked strings are bright at attack and dark at sustain because high frequencies decay faster than low frequencies.

Priority for Synth chapter:

1. Amp ADSR with sustain at 0% - sound dies away naturally even if note is held, with long decay and release for gradual fade
2. Low-pass filter with separate filter envelope - brightness decays independently from amplitude, creating that characteristic pluck timbre
3. Different waveforms - square, sawtooth, triangle in addition to sine

This gets us 80% of the harp sound. LFO tremolo is just polish.

----

When introducing waveforms beyond sine, we'll use a two-step pedagogical approach:

1. Start with additive synthesis - demonstrate how complex waveforms like square waves can be built by overlaying multiple sine waves at different harmonics. This teaches the fundamental concept that all periodic sounds are sums of simple sines.

2. Experience the limitations - show that additive synthesis needs many harmonics to sound right, is computationally expensive, and has aliasing issues.

3. Implement waveforms directly - generate square, sawtooth, and triangle waves with simple math formulas for efficiency.

## On redesigning envelope to control duration

Our current envelope design is flawed. We discovered this while trying to make plucks sound more realistic.

**Current problem:**
- `tone(frequency, duration)` defines how long the sound lasts
- `envelope(source, A, D, S, R)` just shapes the amplitude within that fixed duration
- This means: a 1-second tone will always last 1 second, regardless of ADSR settings
- Real plucked strings don't work this way - they have a natural decay time that can't be "held"

**The insight:**
Real synthesizers and instruments have the envelope control duration, not the tone. The envelope has a gate time - how long the "key is held" - which determines total duration:

Duration = Attack + Decay + GateTime + Release

For plucks: gate time = 0, sustain = 0%, so sound dies naturally during decay phase.
For sustained instruments like flute: gate time is how long you blow, sustain level is maintained during that time.

**New design:**
```js
tone(frequency)                                    // infinite oscillator
envelope(source, attack, decay, sustain, release, gateTime)  // controls duration
```

For pluck:
```lisp
(envelope (tone 261.63) 0.01 1.3 0 0.3)  // no gate, dies after 1.61s
```

For flute:
```lisp
(envelope (tone 440) 0.05 0.05 0.9 0.1 2.0)  // held for 2s, total 2.2s
```

**This exploration revealed:**
- Our architecture needs to match real synth design for proper instrument behavior
- Same tone with different envelopes = different durations naturally
- Plucks, sustained instruments, percussive sounds all work with same primitives
- Envelope is not just amplitude shaping - it defines the sound's lifetime

**Trade-off:**
This makes code more verbose - passing 4-5 parameters every time you want a sound. But this can be remedied by introducing musical instrument abstractions or specialized functions with fixed ADSR properties:

```lisp
(pluck 261.63)           // predefined pluck envelope
(flute 440 2.0)          // predefined flute envelope with gate time
(harp 261.63)            // harp-specific ADSR
```

These instruments become building blocks that hide the complexity while still using the flexible primitives underneath.

This will be the first step in the Synth chapter refactor.
