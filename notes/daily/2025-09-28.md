## On how Lyre code does not look like music

The syntax is too noisy. Instead of capturing the ideas of a musical score, we use the implementation words.

```lisp
(sequence
  (parallel
    (tone D3 2000)
    (sequence
      (tone A5 500)
      (tone F#5 250) (tone G5 250) (tone A5 500)
      (tone F#5 250) (tone G5 250))))
```

Look at all the times we have to write - so repetitive, despite _time_ being present in every note. This made mw think that maybe we can have a define the musical expression first by defining its' time unit and then provide the pitch sequence like so `(t 100 (A5 G4 F#4))`.

Note how I also got rid of the `tone` function - looks and reads much better, worth doing.

But this works if the times are all the same. In Canon they are not however. I came up with the following notation - `.A4` for one time unit, `:A4` for two time units, and `.:A4` for three time units and so on. Might have a global variable `.` that is set by `(set! . 100)` for 100ms time unit.

This way we can express the times in a compact way. Again, no idea how to do it, maybe syntax sugar, which means a viable macro system.

Ideally I'd like for it to look like this:

```lisp
(set! . 250) ; set time unit to 250ms

(harmony
  (::D3       | ::D3      )
  (:A5 F#5 G5 | :A5 F#5 G5))
```

__NOTE__ that `F#5` and `G5` are one time unit each, so the `.` time prefix can be omitted.

Oh yes, I also replaced the `parallel` with `harmony` which sounds more musical.

I like the direction this is going, but I am now unsure if the current primitives are the right ones. Anyhow, I see the biggest technical challenge being the macro system. We can use the `define` for now to set `.`.
