## On Static Code Blocks and Storage

We now have *static code blocks* that automatically make demo code read-only while keeping interactive exercises editable. Blocks without tests become static, distinguishing between code meant for demonstration versus hands-on learning. This provides better UX by preventing users from accidentally editing example code.

The *sequential indexing* approach for storing user solutions broke when we added static blocks, since it shifted the indices of all blocks below them. We solved this by implementing *content-based hashing* where each block gets a stable identity based on its initial code content rather than position. Now blocks can be freely moved, reordered, or have static blocks inserted without breaking saved solutions.
