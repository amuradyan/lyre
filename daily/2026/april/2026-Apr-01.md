## On the minus sign collision

The `-` prefix is currently sugar for `sequence` in the tokenizer: `-(expr1 expr2)` becomes `(sequence expr1 expr2)`. If we introduce arithmetic operators for modular synthesis (`+`, `*`, `-`), the minus sign collides - `-20` would be parsed as a sequence operation, not negative twenty. Need to resolve this before arithmetic can land. Options: rename subtraction (`sub`), change sequence sugar, or context-sensitive parsing.

## On error reporting

The evaluator does not validate or report malformed code. Unknown operators throw at runtime, but there is no upfront checking - no arity validation, no type checking, no helpful error messages pointing to the problematic expression. Previous notes mention tab error indication in the UI (Oct 2025), but nothing about the language itself producing better diagnostics. This will matter more as the language grows.
