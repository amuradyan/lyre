# Daily Note - April 10, 2026

## Issues from Previous Notes

- `harmony` should be rewritten to parallel, and `sequence` should get a friend that applies a fadeout between notes. `mix` needs a friend too - need to think more about primitive counterparts and sound smoothing.
- Visual tools: env inspector attached to lyre codeblock, and expression highlighting during evaluation.
- Error reporting: no validation or diagnostics in the evaluator.
- Inconsistent sugar: `.C4` and `C4:` play as expected but `C4` alone does not. Decide whether to allow bare note names as sounds or disallow since no time means no sound.
- lambdas: do we need two kinds of lambda, or is one enough? Stream /no args, yields next value/ vs function /takes args, returns value/. In Lisps, a generator is just a closure over mutable state.

## On imports

I think we might need imports and modules once we introduce lambdas. It would be convenient to define the mechanical parts of the piece and have the piece written out in a separate file that imports the machinery. I wonder if modules imply top-level bindings, or if we can get by with `let`.

Bonus: This also allows for sharing code between pieces, and for building a library of reusable patterns.
