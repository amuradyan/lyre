## More on modules

Patches as modules.

```lisp
(patch math (x y)
  (export .)

  (let
    (. 0.1
     a 1
     b 2
     z (+ a b)))

     (+ x y z))

(patch sos
  (import . from math)

  (let
    𝄩 0)

    ;  3 shorts         3 longs       3 shorts
    -(A4: A4: A4: 𝄩: .A4 .A4 .A4 𝄩: A4: A4: A4:))
```

Once this file is loaded the memory looks like this:

global env
  prelude
    - A1...G8, attack, decay, triangle, flat, wrap, ....

  math [(x y), (+ x y z)]
    - ., a, b, z
    - all from prelude

  sos [(), -(A4: A4: A4: 𝄩: .A4 .A4 .A4 𝄩: A4: A4: A4:)]
    - 𝄩
    - . (from math)
    - all from prelude

Not sure about the import export mechanism yet.

----

So the `let` stays as is - a local unnamed env that wraps the expression/s/. We introduce a `define` - a top-level named env that can be imported and exported, can be used only once and is allowed in patched only after the `import\export` sections /if present/.

Here are a few examples:

```lisp
; The simplest patch a.k.a a lambda
(patch add (x y)
  (+ x y))
```

```lisp
; A patch that's also a namespace
(patch math (x y)
  (export a b c)

  (define
    a 1
    b (+ 2 a)
    c 3)

  (let
    (z (+ a b c))

     (+ x y z)))

; In another file
(patch test
  (import math)
  (import a b from math)

  (+ (math 2 3) a b)) ; should evaluate to 17

```

Basically a module is something that

- defines it's own namespace
- explicitly states what it exports and imports
- might have internal state and execution logic

? Both arguments and imports stand for the same idea of adding something to the namespace of the clojure. Do we have two things that do the same?
